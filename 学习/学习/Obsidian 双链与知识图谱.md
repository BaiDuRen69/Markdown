 双向链接是 Obsidian 区别于传统笔记软件的核心能力：它不是简单的超链接跳转，而是一种让知识之间**相互感知**的机制——连接两个笔记时，关系在两端同时可见。

## 前置设置

设置 → 文件与链接 → 链接 → 使用 Wiki 链接

> 注意：开启 Wiki 链接后，笔记可能无法在其他 Markdown 平台上正常展示。

## 一、内部链接：`[[ ]]` 语法

在 Obsidian 中，用 `[[笔记名]]` 即可创建指向另一篇笔记的链接。

输入 `[[` 后，Obsidian 会自动弹出搜索框，支持模糊匹配笔记名称。中文输入法下可用 `【【` 来触发。

**示例：**

```markdown
## 我的学习笔记

学习 [[Python 基础]] 时，需要先理解 [[变量与数据类型]]。
这些概念在 [[面向对象编程]] 中也会用到。

可以参考 [[设计模式]] 中的工厂模式实现。
```

点击链接即可跳转到对应笔记。若指向的笔记尚不存在，Obsidian 会显示为灰色链接，点击后自动创建对应空白笔记——这个特性让你可以**先草拟链接，再逐篇填充内容**。

### 别名链接

当文件名不够自然时，使用 `[[文件名|显示文字]]` 语法让链接文字更符合上下文：

```markdown
在学习面向对象时，[[python-oop-advanced-2024|Python 面向对象详解]] 是一篇很好的参考文章。
```

**更好的做法**：在目标笔记的 Front Matter 中设置 `aliases`，之后所有指向该笔记的链接都可以使用别名：

```yaml
---
aliases:
  - Python OOP
  - Python 面向对象
  - Python 类教程
---
```

> 推荐在笔记 Front Matter 中定义标准别名，而不是每次用管道符 `|` 临时改写。别名统一管理，修改一次全库生效。

## 二、块引用与标题引用

除链接整篇笔记外，还可以精准引用笔记中的特定段落或标题。

### 2.1 标题引用

使用 `[[笔记名#标题]]` 直接链接到笔记中的某个标题位置：

```markdown
详见 [[Python 基础#列表推导式]] 中的示例代码。
配置方法参考 [[环境搭建#macOS 安装步骤]]。
```

### 2.2 块引用

在目标段落的末尾添加 `^块ID`，然后在其他笔记中用 `[[笔记名#^块ID]]` 引用：

**Step 1 — 定义块（在「Python 基础」笔记中）：**

```markdown
列表推导式是 Python 中创建列表的简洁语法，
它可以将循环和条件判断写在一行内。 ^list-comp-def
```

**Step 2 — 引用块（在另一篇笔记中）：**

```markdown
如 [[Python 基础#^list-comp-def]] 所述，列表推导式能大幅简化代码。
```

引用块在目标笔记中会以嵌入渲染的方式显示原文内容，而不仅仅是一个跳转链接。

### 2.3 嵌入整篇笔记或段落

在链接前加感叹号 `![[笔记名]]`，可将目标笔记的完整内容嵌入当前笔记：

```markdown
## 常用代码片段

![[Python 列表操作速查]]
![[环境搭建#环境变量配置]]
```

> 嵌入适合用在汇总型笔记中——比如创建一个「常用参考」笔记，嵌入多个速查笔记的内容，形成仪表盘视图。

## 三、反向链接面板

这是 Obsidian 最有价值的特性之一。

打开一篇笔记时，右侧面板的「反向链接」区域会列出**所有引用了当前笔记的其他笔记**。

**举例：** 你写了一篇「闭包」笔记，某天写「Python 装饰器」时链接了它，几周后在「JavaScript 高级函数」中又链接了它。当你打开「闭包」的瞬间，这些关联自动呈现在眼前——不需要手动维护索引。

### Linked Mentions vs Unlinked Mentions

| 类型 | 含义 |
| --- | --- |
| **Linked Mentions** | 已用 `[[双链]]` 语法显式链接到当前笔记的地方 |
| **Unlinked Mentions** | 提到了当前笔记标题文字、但未加 `[[ ]]` 链接的地方 |

Unlinked Mentions 是发现「遗漏链接」的利器——你可能在几篇笔记中都提到了「闭包」，但忘了加双链。

## 四、关系图谱

关系图谱用可视化方式展示笔记之间的链接网络。

### 4.1 局部图谱

在任意笔记中，右上角「更多选项 → 打开局部图谱」，显示以当前笔记为中心的链接网络。

- 默认显示深度：1 层（直接邻居）
- 可调整为 2~5 层以看到更广的关联

### 4.2 全局图谱

点击左侧边栏的图谱图标，查看全库链接关系图。

图谱中的节点含义：

- **节点大小** → 被链接次数越多，节点越大，自然突出核心概念
- **连线粗细** → 双向链接的笔记连线更粗
- **节点颜色** → 可通过分组功能按路径、标签、文件名等条件分配

### 4.3 图谱分组与过滤

在全局图谱设置中创建分组规则：

```
Group #1: 编程笔记
  - path: 编程/
  - 颜色：蓝色

Group #2: 读书笔记
  - path: 阅读/
  - 颜色：绿色

Group #3: 日记
  - path: 日记/
  - 颜色：灰色
```

通过分组，图谱能一目了然地展示不同领域的规模大小和交叉关系。

过滤器可按关键词、标签或文件路径隐藏不需要显示的节点，避免图谱过于密集。

> 图谱更像一面镜子，反映你已有的知识结构，而不是导航工具。不要花太多时间让它「好看」——真正的价值在于暴露出孤立的知识点和意外的跨界关联。

## 五、Unlinked Mentions：补全知识图谱

反向链接面板底部的 Unlinked Mentions 区域，列出所有提到当前笔记标题但未加双链的地方。

定期检查 Unlinked Mentions 是一种低成本的知识整理方式：点击每条旁边的「链接」按钮，一键补上 `[[双链]]`。

这类似于给知识网络「补漏」，让原本隐形的关联变成显式链接。

## 六、双链写作实操建议

| 阶段 | 做法 |
| --- | --- |
| **初写时** | 想到什么概念就大胆加 `[[链接]]`，哪怕目标笔记还不存在。先建立框架，后填充内容 |
| **写完时** | 快速扫一眼 Unlinked Mentions，确认该加链接的关键词是否遗漏 |
| **定期维护** | 浏览全局图谱，观察是否有大量孤立节点。如有，考虑连接到已有核心笔记 |
| **避免过度** | 不是每句话都需要变成链接。只链接对理解当前内容有实质帮助的笔记，宁少勿滥 |
